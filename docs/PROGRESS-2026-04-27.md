## Addendum — 2026-04-27 M-1 phone-418 JSX migration shipped

Format-only conversion. Phone-418 was the lone holdout from the repo's
JSX/Vite norm — every other platform (tablet, desktop, campaign,
phone-341, tablet-verses, tablet-rewardmode, tablet-sim) is a Vite JSX
module under `src/entry-*.jsx` + `*.html` entry pages; phone-418 was a
single standalone HTML file with CDN React script tags and
`React.createElement(...)` chains. Architecture.md's intended structure
acknowledges no exceptions; phone-418's status as exception was
undocumented except in HANDOFF-2026-03-23v12. Migration brings it in
line so phone-418-verses can be a JSX peer and the toolchain is
unified across the repo.

**Scoping decisions (locked at session start):**

1. **Format conversion only — zero behavior changes.** Sets the gate.
2. **Version number v13.0** (not v12.5) — format change is significant
   enough for a minor bump per CLAUDE.md.
3. **Idiomatic JSX conversion** (not "minimal" preserving
   `React.createElement(...)` chains). Reasoning: every other platform
   uses idiomatic JSX, and the tablet behavior-parity comparison is
   only meaningful with JSX-to-JSX diffs.
4. **CSS handling — match repo norm.** No `.css` file (the repo has
   zero of them). Per-element styling stays as inline `style={{}}`.
   Page-level CSS reset + body/`#root` styling + `@keyframes` all
   live in a single `<style>` element rendered at the bottom of the
   component, matching tablet, phone-341, tablet-verses. iOS
   browser-fallback CSS (`min-height: -webkit-fill-available`,
   `-webkit-tap-highlight-color`) preserved.
5. **Test plan:** build verification + manual playthrough on iPhone
   (or 418px Chrome devtools) + deep tablet behavior-parity comparison.

**What shipped:**
- Created [phone418.html](../phone418.html) (mirrors
  [phone341.html](../phone341.html)).
- Created [src/entry-phone418.jsx](../src/entry-phone418.jsx)
  (mirrors [src/entry-phone341.jsx](../src/entry-phone341.jsx)).
- Created [platforms/phone-418/match3-v13.0-418px-phone.jsx](../platforms/phone-418/match3-v13.0-418px-phone.jsx)
  — converted from v12.4 HTML; idiomatic JSX; npm React imports;
  inline `style={{}}` for per-element styling; bottom `<style>` block
  for page-level CSS + 4 `@keyframes`; `export default Match3Game`.
- Updated [vite.config.js](../vite.config.js) — replaced direct HTML
  reference with `phone418.html` rollup input.
- Updated [index.html](../index.html) line 104 link from raw HTML
  path to `phone418.html`.
- Archived `match3-v12.4-418px-phone.html` to
  `platforms/phone-418/archive/`.

**Build verification:** `npm run build` clean, 63 modules transformed
in 901ms, zero warnings. `phone418-*.js` bundle 50.52 kB (gzipped
15.32 kB) — comparable to phone-341 (45.50 kB), as expected for a
peer phone platform. Bundle sizes for other platforms unchanged,
confirming nothing else was disturbed.

**"Banked" naming preserved verbatim** — Session T-1 will rename
across all platforms in one disciplined pass. Renaming during the
migration would have muddied the regression check (was the breakage
JSX conversion or rename?) and left phone-418 inconsistent with the

## Addendum — 2026-04-27 Phone-418 v13.0 vs Tablet v11.12 parity comparison

Run as part of M-1's test plan. Detailed below.

**Identical (gameplay constants).** All scoring rules, multipliers,
thresholds, and rule constants match exactly: ROWS/COLS,
MIN_MOVES/MAX_MOVES, BASE_TARGET/TARGET_VARIANCE, WIN_BONUS_PER_MOVE,
EARLY_END_BONUS_PER_MOVE, BONUS_ROUND_MULTIPLIER (1.5),
DIFFICULTY_INCREMENT_MIN/MAX, BONUS_MOVE_INTERVAL (10000),
BANKED_MOVES_CAP (99), BANKED_MOVES_WARN (90), ANIMATION_SPEED,
MAX_DPR, FRAME_SKIP. Banked-moves logic, bonus round, run tracking,
end-confirm, special-tile core rebalance — all match tablet v11.9-era
logic.

**Intentional differences (form factor / storage scoping).**
TILE_SIZE: tablet 50, phone 40. TILE_GAP: tablet 4, phone 2 (smaller
tiles + tighter gap for narrower screen). Banked-moves localStorage
key: tablet uses shared `BANKED_KEY` from `core/AdminPanel.jsx`;
phone uses phone-scoped `match3_phone418_bankedMoves`. Run-tracking
keys similarly phone-scoped. Per a 2026-03-23 design decision so
iPad and iPhone have distinct runs.

**Real gaps — sync drift, not migration regressions.** Phone-418 v12.4
(J-port) brought it to parity with tablet **v11.9**. Tablet has shipped
v11.10–v11.12 since, plus v11.7 (Session C) and v11.8 (Session D)
that never landed on phone. The migration to v13.0 preserved the v12.4
baseline verbatim, so these gaps are inherited:

1. **v11.7 hypernova rework — "amplification, not interference."**
   Most significant gap. Tablet's hypernova fires specials in the
   5×5+row+col footprint, preserves specials outside, clears half of
   non-specials outside (30-tile floor). Phone-418 v13.0 still has
   v10.1-era logic: solo hypernova never touches specials; combos
   like `hypernova+hypernova` clear ALL non-specials. **Real
   gameplay divergence.** Hypernova feels different on phone than
   tablet. M-2 will port.
2. **AdminPanel integration.** Tablet imports `AdminPanel,
   defaultStats, STATS_KEY, BANKED_KEY` from `core/AdminPanel.jsx`.
   Phone-418 has none — no `?admin=1` URL access, no long-press-score
   panel, no scoring history.
3. **`recordGameResult()` stats system.** Tablet writes unified
   `match3_stats` JSON to localStorage on every game end. Phone-418
   writes only separate `match3_highScore`/`match3_highCombo`/
   `match3_highTurnScore` keys.
4. **v11.8 scoring history panel + slow-motion playback.** Admin-only,
   tablet only. Acceptable to skip on phone form factor.
5. **v11.12 verses → arcade carry banner.** Tablet reads
   `m3_arcade_carry_from_verses` on mount. Phone-418 has none — but
   no phone-418-verses exists yet, so unused. Wire when phone-418-verses
   ships.
6. **`HYPERNOVA_MIN_TILES_CLEARED = 30` constant extraction.**
   Cosmetic — phone hardcodes `30` inline, tablet has it as a named
   constant. No behavior difference.

**Migration verdict.** Clean. v13.0 preserves v12.4 verbatim, just in
JSX form. Build clean, bundle size in expected range. Behavior risk:
low (no logic changes). Sync gap with tablet: real but pre-existing;
the migration didn't widen or narrow it.

## Addendum — 2026-04-27 M-2 phone-418 v11.7 hypernova rework shipped

Backport of tablet's v11.7 "amplification, not interference" hypernova
logic from `match3-v11.12-tablet.jsx` (Session C, 2026-04-21) to
phone-418. Surfaced 2026-04-27 as the highest-priority sync gap during
M-1's parity comparison and shipped as a follow-up the same day.

**What changed in v13.1 vs v13.0:**

- **Solo hypernova** (`activateSpecialTile` case `'hypernova'`): 5×5 +
  row + col footprint now adds ALL tiles including specials; specials
  in the footprint chain into the cascade like any other special
  sweep. Outside the footprint: half of non-specials cleared
  randomly; specials preserved. 30-tile floor for sparse boards.
  v13.0 had v10.1-era logic where solo hypernova explicitly skipped
  all specials (the comment line `// No chainedSpecials — hypernova
  never touches specials` was removed).
- **`hypernova+hypernova` combo:** two footprints (each fires
  specials in its zone via cascade scan) + half of non-specials
  outside combined footprints. Distant specials preserved. v13.0
  cleared ALL non-specials.
- **`hypernova+supernova` combo:** same shape (both share 5×5+row+col
  footprint). v13.0 cleared ALL non-specials.
- **`bomb+hypernova` / `cross+hypernova` / `hypernova+line` combos:**
  hypernova footprint fires specials in its zone + X's solo effect
  (3×3+row+col / row+col / row) fires specials in its path + half of
  non-specials outside combined primary zones. Distant specials
  preserved. v13.0 cleared ALL non-specials.
- **Visual timing on hypernova events:** cascade stagger 400 → 480ms
  (`HYPERNOVA_CASCADE_SLOWDOWN = 1.2`); match-to-clear transition
  400 → 500ms (`HYPERNOVA_MATCH_TRANSITION_MS = 500`). Applied via
  `isHypernovaEvent` flag inside `activateSpecialCombination`.
- **Constants extracted:** `HYPERNOVA_MIN_TILES_CLEARED` (30),
  `HYPERNOVA_CASCADE_SLOWDOWN` (1.2), `HYPERNOVA_MATCH_TRANSITION_MS`
  (500). Phone hardcoded `30` inline before; the other two are new.

**What was intentionally NOT ported.** Tablet's v11.8 admin
slow-motion playback hooks (`playbackSpeedRef.current || 1`
multipliers in `getCascadeDelay` / `getCascadeDuration`). Phone-418
doesn't have AdminPanel integration yet (separate deferred work),
so there's no `playbackSpeedRef`. The cascade-slowdown unit delay is
unscaled here. When AdminPanel + playback eventually port to
phone-418, the playback scaling layers on top of the v11.7
slowdown — it's already structured for that.

**Points unchanged.** Solo hypernova 5000, dual hypernova 10000,
hypernova+supernova 8000, bomb/cross/line+hypernova 6000.

**Build impact.** phone418 bundle 50.52 → 51.54 kB (+1.02 kB);
gzipped 15.32 → 15.79 kB (+0.47 kB). Other platforms unchanged.

**Files touched:**
- New: [platforms/phone-418/match3-v13.1-418px-phone.jsx](../platforms/phone-418/match3-v13.1-418px-phone.jsx)
- Archived: `platforms/phone-418/archive/match3-v13.0-418px-phone.jsx`
- Updated: [src/entry-phone418.jsx](../src/entry-phone418.jsx) (import path),
  [index.html](../index.html) (link description).

**Playtest A/B suggestion.** Phone-418 has three behaviorally distinct
versions accessible from `archive/`: v12.4 (HTML, original), v13.0
(JSX migration, gameplay-equivalent to v12.4), v13.1 (current,
v11.7 hypernova). The v12.4↔v13.0 pair is the M-1 regression check;
v13.0↔v13.1 is the M-2 hypernova-feel A/B. Trigger a hypernova
combo in each and compare cascade reach + survival of distant
specials.

**"banked" naming still preserved.** T-1 (cross-platform terminology
rename) remains the next deferred follow-up.
