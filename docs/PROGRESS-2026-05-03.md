### F-1: Time-attack grace window port

User picked Session F-1 ("desktop time-attack grace") from the rolling what's-next as the smallest of Session F's three pieces. Port from campaign tablet v1.25's pattern, established 2026-04 (already field-tested in campaign). Closes the long-standing "time attack: score undercounted if timer fires mid-cascade" bug that has been carried in DEFERRED's "Known bugs" section.

**Six-decision scoping pass per CLAUDE.md scoping discipline.**

1. **Pre-flight** — verified time-attack's `addTimeExtension` calls `setTimeRemaining(prev => prev + amount)` (so an extension landing during grace can re-arm the timer; the watcher pattern works). Identified two game-end paths that could be affected: the timer-effect setTimeout (replaced by grace) and `endGameSaveMoves` (untouched; player-initiated, not timer-initiated). `useBonusMove` unchanged (sets timeRemaining = 5; timer effect resumes naturally).
2. **Port shape** — Option A (full port: graceActive useState + watcher useEffect + extension re-arm) over Option B (just bump the existing 100ms setTimeout to 1500ms with no re-arm). B doesn't actually fix the bug.
3. **Grace duration** — 1500ms, same as campaign. Field-tested; consistency wins absent a specific reason to diverge.
4. **Bonus-moves prompt interaction** — if a cascade earns a bonus move mid-grace, don't surface the prompt; bank the move for next game. Matches campaign behavior; switching tracks mid-flight adds state-machine complexity for a rare edge case.
5. **Version + label bump** — patch (v12.3 → v12.4).
6. **Doc updates + commit shape** — F-1 + version-label drift audit bundled into one commit; PROGRESS roster + addendum + DEFERRED known-bug strike + Done entry.
