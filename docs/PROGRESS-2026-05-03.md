## Addendum — 2026-05-03 T-3b storage-value migrations + lockstep shipped

First (and only) session of 2026-05-03. Closes the T-3 data event by shipping the storage-string VALUE migrations + the phone arcade ↔ phone-verses lockstep that T-3a left for the second half. Total of 8 storage keys migrated via 7 single-key + 1 prefix-walk helper, all running once at module load via core's new `migrateBonusMovesKeys()` orchestrator.

**Scoping pass — six decisions, locked one-at-a-time per CLAUDE.md scoping discipline.**

1. **Pre-flight inventory** — confirmed the 6 documented strings (1 core + 5 phone) but **surfaced 2 additional `bankedMoves` storage values not on DEFERRED's T-3b list:** desktop's `'match3_desktop_bankedMoves'` and time-attack's `'match3_timeattack_bankedMoves'`. Both files' T-2 in-file comments said "T-3 migrates this," but DEFERRED's enumeration only covered 6 of the 8 strings. User chose option (a): bundle desktop + time-attack into T-3b. Final scope: 8 storage keys + 1 export-key rename + 4 platform version bumps.
2. **Migration code shape** — Option A (generic helper + per-key calls) over Option B (monolithic function). T-3a's `migrateStatsBlob()` was naturally monolithic for one-key/multiple-fields; T-3b is the opposite shape (8 keys, simple value renames each), so the helper pays for itself. **Stricter idempotency than T-3a** — always removes the old key after attempting migration; preserves new value if both exist; never leaves orphans. Confirmed before locking.
3. **Migration code home + trigger** — same as T-3a (`core/AdminPanel.jsx`, runs at module load). **Critical finding: 3 of 9 affected platforms don't import core** — phone arcade, desktop, time-attack. Each gets a new explicit `import { migrateBonusMovesKeys }` + top-level call. Pre-approved bundle-size hit (a few KB; net same total bytes).
4. **AdminPanel JSON export key flip** — verified no import-from-JSON path exists in `core/AdminPanel.jsx` (handleExport only writes; nothing reads). Old saved export files on user disks stay frozen as-is. Pure code rename, no migration code.
5. **Importer-only version bumps** — **NOT applied for T-3b.** Per the T-3a precedent (vs the T-2 precedent): T-2 bumped importer-only files because the import-line text itself changed (`BANKED_KEY` → `BONUS_MOVES_KEY`). T-3b leaves the API surface unchanged (`BONUS_MOVES_KEY` name preserved; only its VALUE changes inside core). Importing platforms' source files are byte-identical to T-3a. They inherit the new migration behavior at runtime. Tablet, tablet-verses, tablet-rewardmode, tablet-sim, campaign tablet — all unbumped.
6. **Commit shape + implementation order** — single commit forced by phone lockstep; one-way migration confirmed acceptable (same as T-3a). Implementation order lowest → highest risk: core first, then desktop (independent), time-attack (independent), then phone arcade + phone-verses together (lockstep), then docs. Per-step build verifies along the way.
