## Addendum — 2026-05-02 P-2 phone-platform consolidation rename shipped

First (and only) session of 2026-05-02. Bundled rename event covering
both phone platforms + phone-341 retirement + doc updates. Triggered
by user device-test of phone arcade v13.3 (P-1, shipped 2026-05-01)
and visual confirmation that the responsive board work was solid:
"v.13.3 looks fine, except the header still says: 'v13.1.'"

**Sync check at session start.** Confirmed both phone platforms still
share the storage-key VALUE `'match3_phone418_bankedMoves'` (the
verses → arcade carry-out depends on this). No surprise commits to
the in-scope directories since P-2 was scoped on 2026-05-01.

**Mid-session findings (4) — each surfaced organically and got an
explicit pause-and-decide gate before bundling:**

1. **Phone arcade header label bug — bundled.** `match3-v13.3-418px-phone.jsx`
   line 3041 rendered `M3 v13.1-418px` in the in-game header — stale
   since the v13.1 → v13.2 ship and missed again at v13.2 → v13.3.
   Fix folded into P-2's coherence rewrite of the renamed file (since
   that line was in P-2's edit zone anyway). New label: `v13.3.1`.
   Approved by user before bundling.

2. **Phone-verses parallel header label bug — bundled.** Discovered
   during the verses pass: the h1 fallback `<>Verses <span>v…</span></>`
   read stale `v1.5` since v1.0 (N-2). Per archive comparison, every
   archived version v1.0 / v1.1 / v1.2 / v1.3 / v1.4 carries the same
   stale label. The fallback only renders when `VERSES_MODE && versesGame`
   is false — in normal play the header shows the game title, so this
   is a dormant code-path issue, not a user-visible bug. Bumped to
   `v1.4.1` for code coherence. Approved by user before bundling.

3. **Constant rename `PHONE418_BONUS_MOVES_KEY` → `PHONE_BONUS_MOVES_KEY`
   — bundled.** P-2 decision #4 enumerated lowercase forms
   (`phone-418` / `phone418` / `418PX`) for coherence rewrites; the
   uppercase `PHONE418` constant prefix was the case the original
   scope didn't explicitly name. Same coherence logic applies — a
   reader of the file at `platforms/phone-verses/` shouldn't see a
   constant with a `PHONE418` prefix. 14 references, all internal to
   the file. Storage-string VALUE preserved per decision #2. Approved
   by user before bundling.

4. **Fifth `phone418` storage-string surfaced — added to deferred
   sweep.** Phone-verses declares `VERSES_PROGRESS_KEY_PREFIX = 'm3_phone418_verses_'`
   (used as a key namespace for per-game level-completion data). Not
   on the original P-2 inventory of four storage strings. Same
   constraint: renaming the value here orphans player progress
   without a migration. Per decision #2 spirit: preserved verbatim,
   added to the cross-platform terminology + naming sweep entry in
   DEFERRED.md so the future migration covers all five together.
   Captured in v1.4.1's "What stays unchanged" comment block.

**Implementation pattern (per platform).**
- `cp <active>` → `archive/<active>` (frozen historical copy under
  original name)
- `git mv platforms/<old-dir>` → `platforms/<new-dir>`
- `git mv` the active file inside the new dir to its v.X.Y.1 name
- `git mv` the entry file (`src/entry-<old>.jsx` → `src/entry-<new>.jsx`)
- `git mv` the HTML page (`<old>.html` → `<new>.html`)
- Insert new top-of-file version comment block describing the rename
- Apply path/name `replace_all` rewrites in length order to avoid
  partial-match collisions (~6 rewrites per file: phone-418-verses,
  Phone-418-verses, phone-418, Phone-418, PHONE 418PX, PHONE418)
- Hand-edit the in-game header label
- Update `vite.config.js` rollup input
- Update landing-page card in `index.html`
- `npm run build` to verify
