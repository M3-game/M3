## Addendum — 2026-08-09 Session 15: in-game header clipped at the top (phone-verses v2.4, sandbox v1.14)

Player-reported with a screenshot: the top of the white in-game header card
was cut off — its rounded top corner and part of the "See passage" pill sat
above the visible area — and the iOS status bar was drawn over the title
("Habakkuk 3:17–19" running into the cellular signal bars).

### Why the diagnosis took three passes

The intermittency ruled out the obvious explanations one at a time, and the
discarded hypotheses are worth recording so they aren't re-tried:

1. **"Content grew taller than the viewport, and `justifyContent: 'center'`
   makes the top overflow unreachable."** Plausible — the header does grow
   during a round (the bonus-moves row only exists once bonus moves are
   earned, the passage text bar grows as lines reveal, the "· 1.5×" marker
   and drill badge add width). **Ruled out** by the user reporting the header
   sitting correctly *with* four revealed lines and the bonus row showing.
   The content fits; it isn't content height that's toggling.
2. **"Safari's toolbar collapse scrolls the page and the game can't scroll
   back."** **Ruled out** by the user seeing it with both the collapsed pill
   *and* the full-width address bar, and by tapping/dismissing the address
   bar not restoring it.

What survived is that the page has scroll room it should never have had, from
two independent sources, and that the scroll is one-way.

### The four contributing causes (all read directly from the code)

1. **No CSS reset exists anywhere in the project.** No stylesheet file is in
   the repo and no entry file imports one — `src/entry-phone-verses.jsx`
   renders straight into `#root`. So `<body>` kept the browser default 8px
   margin, top and bottom, and with the wrapper at `minHeight: 100vh` the
   document was permanently `100vh + 16px` on every load, regardless of
   content.
2. **`100vh` on iOS Safari is the *large* viewport height** — the height the
   page would have with the toolbars hidden. Whenever the toolbar is showing,
   the visible area is shorter, adding a further ~60–90px of scroll room.
   This is the larger of the two sources.
3. **`touchAction: 'none'` on the wrapper** (there so swipes reach the board
   rather than panning the page) means that once the page *is* scrolled, a
   drag can't bring it back. Nothing resets `scrollTop` — there are no
   `scrollTo`, `scrollIntoView`, or `scrollTop` calls anywhere in the file.
4. **`viewport-fit=cover` + `apple-mobile-web-app-status-bar-style:
   black-translucent`** in the HTML tell Safari to run the page under the
   status bar and notch, with no `env(safe-area-inset-top)` padding to
   compensate — a constant ~47–59px overlap. Constant, so it never explained
   the intermittency, but it's why the status bar sat on the title.

The intermittency was simply whether the page happened to be sitting at
scroll 0.

### What shipped

Three changes, identical on both platforms:

- **Body margin zeroed** — `<style>html, body { margin: 0; padding: 0; }</style>`
  added to `phone-verses.html` and `phone-verses-sandbox.html`. Scoped to
  those two pages so no other platform's layout shifts (see the DEFERRED
  entry: the other nine pages still carry the default margin, on purpose).
- **Safe-area top padding** on the game wrapper: `paddingTop: 'calc(env(safe-area-inset-top, 0px) + 8px)'`,
  written as padding **longhands** rather than the shorthand so the value
  can't be clobbered by property order in the inline style object.
- **`minHeight: '100vh'` → `'100dvh'`** — the dynamic viewport unit tracks
  the height actually visible on iOS. (dvh: Safari 15.4+, Chrome 108+,
  Firefox 101+. Without support the declaration is dropped and the purple
  wrapper sizes to its content — cosmetic, not a break.)

### Decision: `justifyContent: 'center'` left alone

Top-anchoring the wrapper would make top clipping structurally impossible,
but it also moves the game to the top of the screen on every device where it
currently fits — a visible change to every session. User direction was to fix
the actual cause first and see whether that's enough. If clipping recurs,
this is the next lever.

### Verification

`npm run build` clean. Confirmed in the built output, not just the source:
`100dvh` and `env(safe-area-inset-top, 0px) + 8px` both present in
`dist/assets/phoneVerses-*.js` and `dist/assets/phoneVersesSandbox-*.js`, and
the `html, body { margin: 0; padding: 0; }` rule present in both dist HTML
files. No stale references to the v2.3 / v1.13 filenames remain in `src/` or
any HTML file.

**Not verified on a real device** — the fix addresses causes read from the
code, and whether it fully resolves the intermittent clipping needs phone
testing. See the "what's next" note above.
