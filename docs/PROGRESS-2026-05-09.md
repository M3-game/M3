## Addendum — 2026-05-09 VS-1 v1.3 rescue redesign + Mechanic D shipped

Five mechanic changes bundled in one ship after a multi-message scoping
discussion that worked through six decisions individually. Bundled doc
work: design notes rewritten v1 → v2 correcting v1's §2 errata about
the rescue mechanic.

**Scoping pass.** Decisions worked through one at a time per CLAUDE.md
scoping discipline:

1. **Mechanic C trigger N reduction.** User chose `(total moves) − 9`
   over `3 or 4`. On a 12-move game = 3.
2. **Mechanic D — post-hypernova bias suppression.** User chose to
   ship #3 from the design doc; suppression value = 8%.
3. **Mechanic C drop-weight rebalance.** User chose 35/35/20/10 ("the
   stated ratios" from design doc §6) to keep hypernovas rare.
4. **Bias spike on rescue-fire turn.** User initially didn't name this
   in their first decisions reply; on follow-up confirmed inclusion in
   v1.3 (option 1 of three: bundle now). Value = 30% (default proposed).
   Timing = drop turn (not next turn). Scope = whole turn-cycle
   including same-turn cascades, matching the hypernova-suppression
   "whole turn" treatment for parallelism.
5. **Trigger move = dynamic per level.** User chose dynamic over
   hard-coded-3, since verses-game level lengths range 5–28 moves.
   Floor at 0 for short levels (≤9 moves arm immediately).
6. **Rescue window 4 → 7 turn-completes.** User raised this during
   the doc-vs-shipped Q1 discussion; "let's go with 7 — although it
   will most likely fire before then."

**Discovery during scoping (Q1).** The `verses-game-design-notes-v1.md`
§2 description of the rescue mechanic did not match shipped v1.2
behavior. v1's §2 said "trigger N=6 → 50% one-shot fire when triggered →
50% 5-tile / 50% super-special split"; shipped v1.2 was "trigger move
5 → 4-turn rescue window → per-turn 50% roll → weights 25/25/30/20."
User confirmed v1's §2 was authored from a discussion in claude.ai
without code access. Resolved in v1.3 by rewriting the doc as v2 with
a §2 errata callout explicitly noting v1's inaccuracy.

**Mechanic glossary (added per user request mid-ship).** User flagged
mid-ship that "Mechanic B" was opaque shorthand they didn't remember
("we came up with the Mechanics days ago, so I don't remember who she
is"). Added a §0 Mechanic glossary to design-notes-v2.md mapping
A/B/C/D to their descriptive names (neighbor-match bias / big-turn
drop / floor-raise drop / hypernova bias suppression). Throughout the
v1.3 file's top comment block and the new design notes, every
"Mechanic X" reference is paired with the descriptive name.

**Implementation.** Five new constants in v1.3
(`FLOOR_RAISE_TRIGGER_MOVE` removed → became `computeFloorRaiseTriggerMove`
function; `FLOOR_RAISE_WINDOW_TURNS` 4 → 7; weights 25/25/30/20 →
35/35/20/10; new `FLOOR_RAISE_BIAS_SPIKE_PCT = 30`; new
`HYPERNOVA_BIAS_SUPPRESS_PCT = 8`). Two new component refs:
`biasOverridePctRef` (live, read by `fillEmptySpaces`) and
`pendingBiasOverridePctRef` (queued by rescue, transferred to live at
end of turnComplete). Floor-raise useEffect restructured from
early-returns to if/else if so the bias-override transfer at the
bottom always runs. `fillEmptySpaces` snapshots the override at the
start of each fill cycle in `biasPct = biasOverridePctRef.current ??
NEIGHBOR_BIAS_PCT` and reads from biasPct. Hypernova hooks added at
two sites: single hypernova in `activateSpecialTile` (line ~3956),
and combo hypernova in `activateSpecialCombination` after
`isHypernovaEvent` check (line ~4034). `restartGame` clears both
override refs alongside the existing floor-raise state reset.
Console logs renamed VS-1.2 → VS-1.3 throughout the floor-raise
effect; new logs `floor_raise_fire` (with `biasSpike` field) and
`hypernova_bias_suppress` (with `source: 'single'` or `'combo'` +
combo string).
