## Addendum — 2026-05-09 VS-1 v1.4 Mech B edge-case suppression + bonus-moves threshold bump shipped (second ship of the day)

Three small adjustments bundled in one ship after a six-decision scoping
pass that the user invited mid-day after the v1.3 ship. Stale-versions
cleanup bundled (removed v1.2 + v1.3 from active dir) per explicit
"sure" on the bundling question.

**Scoping pass.** Six decisions worked through one at a time per CLAUDE.md
scoping discipline:

1. **First-turn definition.** Suppress when `movesUsedRef.current === 1`
   at watcher fire (the qualifying turn was the player's first swap).
2. **End-of-level definition.** Suppress when `moves <= 0` after qualifying
   turn — user clarified "very last move - moves = 0 - drop never appears."
3. **Bonus-moves interaction.** Discovery during scoping: I had thought
   bonus moves might not be wired in verses-sandbox, but verified in
   code that they ARE: earned at 1 per 10K (line 3207ish), persistent
   across games via `match3_phone_bonusMoves_sandbox`, spent via
   "Use bonus moves" prompt at moves=0 OR via victory round. So the
   moves-check needs to be bonus-moves-aware: suppress only when both
   `moves <= 0 && bonusMoves <= 0`. The bigger "remove bonus moves
   from verses entirely" question was raised by user as worth a
   separate session, then user proposed a milder alternative: raise
   `BONUS_MOVE_INTERVAL` from 10K to 25K so bonus moves become a
   "great game" reward rather than a near-guaranteed accumulation.
   Bundled this into v1.4 since it's a single-constant change with the
   same risk profile as a tunable bump.
4. **Instrumentation.** New `[VS-1.4 big_turn_skip]` log with `reason`
   field (`'first_turn'` or `'no_moves_left'`). Existing fire/miss
   logs keep `[VS-1 ...]` prefix since the roll behavior itself is
   unchanged.
5. **Version bump.** v1.3 → v1.4 — small adjustments fit patch cadence.
6. **Stale-versions cleanup bundled.** Removed v1.2 + v1.3 from active
   dir (archive copies preserved). Same pattern as
   [fe5adf1](https://github.com/M3-game/M3/commit/fe5adf1) which
   cleaned up v1.0 + v1.1 in the v1.2 ship cycle.

**Bonus-moves threshold reasoning.** Design notes §5 already defines a
"great game" tier at 25K+ scoring (15-25% of games). At 10K threshold,
median ~14K games earn 1 bonus move on every play, accumulating across
games. At 25K, median games earn 0 → no accumulation creep on typical
play; ~25% of games earn 1 → bonus moves become a "great game" reward;
hot-streak games (40K-110K) still earn 2-4 → preserves the
carry-across-passages benefit user wanted for longer Matt levels (24-28
moves). Larger "remove bonus moves entirely" question deferred unless
25K proves insufficient.

**Implementation.** Mech B watcher useEffect: two new early-return
checks after the existing `count < BIG_TURN_THRESHOLD` and
`_pendingSpecialDrop.kind !== null` guards. Dep array expanded
`[turnComplete]` → `[turnComplete, moves, bonusMoves]` so the closure
captures fresh values for the suppression check (spurious re-runs on
moves/bonusMoves changes during turnComplete=false short-circuit at the
first guard). `BONUS_MOVE_INTERVAL` 10000 → 25000 with inline comment
explaining the rationale.

**Build verifies.** Clean. `phoneVersesSandbox` bundle 81.71 → 81.97 kB

**Scoping pass.** Decisions worked through one at a time per CLAUDE.md
