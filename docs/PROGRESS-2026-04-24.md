## Addendum — 2026-04-24 V-2 shipped (v1.1 → v1.2 → v1.3 post-playtest)

Session V-2 shipped in three passes within the same session:

- **v1.1 first-pass** — implementation followed the V-2 spec in
  DEFERRED.md (the canonical reference, written during the morning
  deep-scoping pass). Playtested by the user immediately after.
- **v1.2 post-playtest polish** — four fixes driven by the v1.1
  playtest, rolled into the same session since they're tight
  adjustments rather than new scope:
  1. **Header font revert.** v1.1 applied Georgia to the game-header
     `<h1>` for typographic consistency with the text bar; it fought
     the Arial header chrome. v1.2 drops the override — header stays
     Arial; Georgia is reserved for content typography (text bar +
     passage modal).
  2. **Reveal-on-decrement.** v1.1 fired the chunk reveal at post-
     settle + 200ms beat. Playtest finding: the reveal trailed the
     eye — the player was already scanning the cascade when the
     next chunk appeared. v1.2 fires the reveal the instant a
     successful swap decrements `moves`, so the next chunk is
     visible *during* the cascade. Drops `pendingRevealRef`, the
     settle-wait effect, and `CHUNK_REVEAL_BEAT_MS`; keeps the
     250ms CSS fade-in. Net code: simpler (one effect instead of
     two).
  3. **Text-bar tightening.** v1.1 set `minHeight: 96px` with
     `justifyContent: flex-end`, which left empty whitespace at the
     top of the container until 3 chunks were revealed, and the
     3-chunk max state was too tall to fit board + banner + text
     bar in a standard viewport. v1.2 drops min-height (container
     sizes to content), tightens padding (14px 20px → 8px 20px) and
     fonts (current 22 → 19px, prior 15 → 13px, line-height 1.3 →
     1.2). Trade-off: slight downshift of the board across the first
     two reveals (1 chunk → 2 → 3), then stable.
  4. **Start-of-round passage modal.** User ask: show the full
     passage at game start so the player sees the target before
     memorizing. New `showStartModal` state, init true; reuses the
     existing end-of-round passage modal with button-text and
     click-handler branching — `Begin game` at start (closes modal),
     `Play again` at end-of-round (calls `restartGame`). Per user
     request, `restartGame` also re-opens `showStartModal` so the
     passage is seen between rounds. Swap handlers pick up a
     matching `showStartModal || showPassageModal` guard as
     defense-in-depth alongside the existing `moves <= 0` guard.

- **v1.3 header trim** — after v1.2 playtest, the header + text bar
  + board still didn't fit in the user's browser viewport without
  scrolling (couldn't see both score at top and bottom-row tiles).
  Chose the chrome-cut path over shrinking tiles or removing rows
  (which would have changed gameplay dynamics). Changes:
  - Hide the "✨ Specials on board: N" line in VERSES_MODE
    (`!VERSES_MODE &&` guard on the div).
  - Hide the entire combo-indicator + idle-stats div in VERSES_MODE
    (min-height-24px slot goes away, not just collapse-when-idle).
    Score popups over the board still show points + multiplier
    per match, so mechanic feedback stays where the player's eye
    is already focused.
  - Header card padding `12px 20px → 10px 20px`, margin-bottom
    `20 → 14px`, minHeight `110 → 80px`, all in VERSES_MODE only.
  - Kept: title, Score, Moves, Bonus moves (when >0), Target,
    dark/light toggle.

Net build impact: verses bundle 64.37 → 65.56 kB (v1.0 → v1.3).
v1.3 came in ~1 kB smaller than v1.2 (66.59 → 65.56 kB) because
the guarded render branches are tree-shaken when VERSES_MODE is a
module-constant true — the build drops the combo-indicator JSX.
v1.2 had already been slightly smaller than v1.1 (66.78 → 66.59 kB)
thanks to the dropped settle-wait reveal pipeline.

The remaining implementation-note prose below still applies to v1.2
(wiring, versesLevel flattening, `restartGame` reset semantics,
gameState staying 'playing'). Two things changed from the v1.1
description:
- Chunk reveal is now one effect (moves-decrement fires reveal
  directly, no pendingRevealRef). End-of-round still waits for board
  quiet (isAnimating / combo / pendingSpecials) before its 2.5s
  modal hold.
- `restartGame` also sets `showStartModal = true` so the passage
  viewer re-appears between rounds.

**Implementation notes (not already in the spec):**

- **Settle-callback hook** (flagged in the V-2 spec as a commit-time
  follow-up): reveals are triggered by a pair of effects, not by
  splicing into the existing `setIsAnimating(false)` call sites.
  - A moves-decrement detector (`useEffect` on `moves` with a
    `prevMovesRef`) arms `pendingRevealRef` when moves decreases.
    Using moves as the trigger means only successful swaps (which
    consume a move) arm a reveal — non-match snap-backs don't, and
    `restartGame` resets the ref so the 0 → 12 bump isn't misread as
    a decrement.
  - A post-settle reveal effect on `[turnComplete, isAnimating,
    combo, pendingSpecials.length, gameState, moves]` fires a 200ms
    timer once the board is quiet, commits the reveal, and clears
    the pending flag. Non-reactive ref by design — this avoids
    touching the tablet cascade pipeline, which keeps the V-2 diff
    contained and preserves the pure-tablet v11.11 gameplay inside
    the match-3 loop.

- **Bonus-moves-prompt guard site** (also flagged in the spec):
  handled at the top of the existing arcade game-end effect's
  timeout body — a single `if (VERSES_MODE) return;` short-circuits
  before any of the three resolution branches (target-hit prompt,
  bonus-round resolution, moves=0 resolution). The earlier
  `pendingThreshold` bail and the separate bonus-move-accrual effect
  both stay live, so the 10k-threshold tracking keeps ticking —
  earned bonus moves sit idle at V-2 (no prompt consumes them) and
  get zeroed on Play Again. V-4 replaces the early-return with the
  memorize-mode victory-round + consume + arcade-handoff logic.

- **`gameState` never transitions in VERSES_MODE.** The arcade
  `won`/`gameover` transitions live inside the guarded flow above,
  so a VERSES_MODE game stays in `gameState === 'playing'` from
  first swap through passage-modal dismissal. Arcade end banner
  render is additionally wrapped with `!VERSES_MODE` (defensive —
  currently redundant).

- **Play Again** calls the existing `restartGame`. VERSES_MODE branch
  reseeds `moves` and `levelTarget` from `versesActiveLevel` (not
  the arcade random), resets `revealedChunkIndex` to 0 (chunk 0
  pre-visible again), clears toast + modal, zeros `pendingRevealRef`
  + `prevMovesRef`, and zeros `bankedMoves` (since V-2 has no
  consumption path; persisting would stockpile dead currency).

- **Build impact.** `dist/assets/verses-*.js` 64.37 kB → 66.76 kB
  (+2.39 kB). Verified Titus chunks are bundled into the chunk
  stream (`Titus 2:11`, `For the grace of God`, `Jesus Christ` all
  present in the emitted JS).

**Scoping-discipline check.** User's scope-adherence feedback rule
held up well — implementation stayed strictly inside the V-2 spec.
Items noticed but not touched: the pre-existing `console.log('Game
end check:', …)` at the top of the arcade game-end effect's timeout
body still fires every tick (now in VERSES_MODE too, since the log
is before the `if (VERSES_MODE) return`). Harmless console noise;
intentionally left for a future cleanup session rather than bundled
into V-2.

**Still-open playtest questions** (from V-2 scoping, now live):
- 200ms settle beat vs. 250ms fade — does the board settle "read"
  before the text shifts, or does the beat feel too long?
- 2.5s passage-modal hold — enough time to absorb the last chunk,
  or too long / too short?
- Target-hit toast duration (2.5s) + gold-✓ contrast on the
  header Target field.
- Georgia at the sizes chosen (22px current / 15px prior / 19px
  modal body) — legible and distinctive, or fighting the rest of
  the UI?

## Addendum — 2026-04-24 Memorize Mode scoping session

Full scoping conversation for a new game mode — **Verses** (memorization
delivery via match-3). Fork from tablet v11.11. Core concept: verses
reveal one chunk per successful swap, riding on top of unchanged
match-3 mechanics. 5 sessions planned (V-1 through V-5). Key locked
decisions:

- **Memorization is purely additive.** No gameplay changes. Match-3
  runs exactly as tablet arcade; chunks reveal as a byproduct.
  Consistent with the "amplify fun, not interfere" corollary in
  DESIGN.md.
- **Moves = chunks.** Each passage sets its own move budget via the
  data (Titus 2:11–13 = 13 chunks = 13 moves).
- **Two-level structure for long passages.** Games can be split into
  sequential levels (e.g., Psalm 91 into 3–4 levels). Hybrid
  progression: strict first pass (must hit target to advance),
  free-replay for individual levels after full game completion. User
  flagged "middle parts are often the hardest" for memorization —
  free replay targets exactly that.
- **Secondary landing page** (Verses picker) on `verses.html`, with
  two-tier navigation (game cards → level-select for multi-level).
  Main `index.html` gets one "Verses" card (normal-visible, not
  admin-gated).
- **Silent 1.5× victory round** at target-hit. No prompt; "end early"
  would stop chunk reveals, which defeats the purpose. Keeps scoring
  reward while preserving memorization flow.
- **Bonus moves** carry level-to-level within a game, persist on
  "Play again" (to let players replay with accumulated rewards), zero
  on picker-exit, and roll into tablet arcade on "Tablet arcade"
  button. Pattern shares future plumbing with DEFERRED Session F's
  campaign → arcade carry — build standalone first, unify later.
- **Target score** = `moves × 300` formula default with optional
  per-level override. Short games may need the override since
  cascade setup is harder with few moves.
- **Stars** — campaign-style 1–5★ per level (tentative — removable
  later if they add noise). Chosen for replay motivation since hybrid
  progression specifically supports re-playing individual levels.
- **Text bar** between banner and board, rolling 3-chunk window
  (current + 2 prior), current emphasized. End-of-level passage
  reveal after ~2.5s delay. At final-game end, passage stays visible
  indefinitely with **Play again** / **Tablet arcade** buttons —
  no auto-dismiss.
- **Content authoring** — drop a new folder under
  `platforms/tablet-verses/games/<slug>/` with a `game.js` file;
  glob-discovery picks it up. `_template/` + README provided;
  `hidden: true` flag for drafts.
- **First games** — Titus 2:11–13 (single-level, 13 chunks) at V-2.
  Psalm 91 (multi-level, 3–4 levels TBD during V-3).

Scoping discipline: decisions worked through one-per-message over the
course of the conversation, with an explicit 7-item roadmap front-
loaded and confirmed before diving in. Reversals during scoping (worth
noting as sign the scoping caught real design questions):
- **Stars:** defaulted no → flipped to yes after user reasoned about
  replay motivation under hybrid progression.
- **Bonus moves on Play Again:** defaulted zero → flipped to persist
  after user framed them as an earned reward rather than per-session
  currency.

The full locked-decisions summary lives in `docs/DEFERRED.md` Memorize
Mode entry, which is the canonical reference for V-1 through V-5.
