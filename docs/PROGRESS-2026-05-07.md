## Addendum — 2026-05-07 VS-1 v1.2 floor-raise + bias 13% shipped (second ship of the day)

Two changes bundled into v1.2: (1) Mechanic A neighbor-match bias
14% → 13%; (2) Mechanic C "Floor-raise drop" — new. Same-day ship
following ~20 games of v1.1 playtest in the morning.

**Rationale.** v1.1 testing showed the score *ceiling* took off
nicely (14% bias raised cluster refills → more natural specials on
big turns → bigger cascades) but the score *floor* was still low.
About 30% of levels never produce a single ≥5-tile match, leaving
the player with only weak 4-tile line clears and no cascade-driving
specials. User wanted two adjustments: a small pullback on bias
(14 → 13) to ease compounding pressure on already-good boards, and
a new mechanic to rescue the bad-board case directly.

**Scoping pass.** Six decisions worked through one at a time over
multiple messages per CLAUDE.md scoping discipline:

1. **Trigger definition.** Single match-event with ≥5 tiles
   cleared (i.e., creates a bomb / cross / supernova / hypernova
   per the engine's existing classification). Hooks into the
   `group.totalUniqueTiles >= 5` check at the three special-creation
   sites in `processMatches`. *Discovery during scoping:* the user
   correctly noted that `cross` is a 5-tile T/L-shape, not 4-tile.
   I'd initially miscategorized it; verifying against the code
   (line 4220 `(rows.size > 1 && cols.size > 1) ? 'cross' : 'bomb'`)
   confirmed the user's framing.
2. **Rescue cancel.** A natural ≥5-match during the rescue window
   disarms — "until one appears" means "until the player no longer
   needs help."
3. **Drop weights on hit.** Bomb 25% / cross 25% / supernova 30% /
   hypernova 20%. Skewed toward the more common 5-tile specials
   with declining probability for the rarer/more powerful
   supernova and hypernova.
4. **Silent.** No popup. The big-turn drop has a "💥 HUGE turn!"
   popup, but the floor-raise rescue would read as "your board is
   bad, here's help" — patronizing in tone. Silent feels respectful.
5. **Version bump.** v1.1 → v1.2. New mechanic technically
   qualifies for a minor bump (1.x → 2.0) per CLAUDE.md, but this
   is sandbox iteration cadence; v1.2 fits.
6. **Naming.** "Mechanic C — Floor-raise drop" — matches the
   user's design intent ("raise the floor"), pairs with Mechanic
   B's "big-turn drop" (both are *drops* fired on turn-completion).
   Constants `FLOOR_RAISE_*`. Shares `_pendingSpecialDrop` queue
   with Mechanic B (overlap behavior: rescue skips its roll if
   queue already populated, no decrement).

**Implementation.** Five new constants
(`FLOOR_RAISE_TRIGGER_MOVE = 5`, `FLOOR_RAISE_WINDOW_TURNS = 4`,
`FLOOR_RAISE_ROLL_PCT = 50`, `FLOOR_RAISE_BOMB_PCT = 25`,
`FLOOR_RAISE_CROSS_PCT = 25`, `FLOOR_RAISE_SUPER_PCT = 30`,
`FLOOR_RAISE_HYPER_PCT = 20`). Five new component refs:
`movesUsedRef`, `bigMatchMadeRef`, `floorRaiseArmedRef`,
`floorRaiseFiredRef`, `floorRaiseRollsRemainingRef`. Refs reset per
level via component remount (VersesGame keys on `slug:levelIndex`)
plus explicit reset in `restartGame`. `movesUsedRef` increments
in `attemptSwap` alongside the existing `turnTileCountRef` reset.
`bigMatchMadeRef` set true at all three special-creation sites in
`processMatches` when `group.totalUniqueTiles >= 5` (or `group.length
>= 5` at the third site, which uses `length` instead of
`totalUniqueTiles`). New useEffect on `[turnComplete]` after the
existing Mechanic B watcher implements the three-step flow:
satisfied → arm → roll. Consumer in `fillEmptySpaces` widened from
hardcoded `kind === 'hyper' ? 'hypernova' : 'supernova'` to a
lookup table covering all four kinds (bomb, cross, super, hyper).
Console logs on every state transition for instrumentation:
`floor_raise_arm`, `floor_raise_fire`, `floor_raise_miss`,
`floor_raise_giveup`, `floor_raise_cancel`, `floor_raise_skip`.

**Bias change.** Single-line: `NEIGHBOR_BIAS_PCT` 14 → 13. Inline
comment notes the v1.0/v1.1/v1.2 history.

**Build verifies.** Clean. `phoneVersesSandbox` bundle 79.93 kB →

## Addendum — 2026-05-07 VS-1 v1.1 neighbor-match bias bump shipped

Single-line tuning bump on phone-verses-sandbox: `NEIGHBOR_BIAS_PCT`
10 → 14. v1.0 → v1.1. All other VS-1 mechanics unchanged.

**Rationale.** User played ~20 games of v1.0 on real iPhone (small but
meaningful sample), built an external analysis/spreadsheet of score
distribution, and decided 10% felt too sparse for a "fun-first"
experience. Discussed two options with Claude.ai: 12% (smaller bump,
larger effect at the score ceiling than the floor per the user's
analysis — Claude.ai's recommendation) vs. 14% (larger bump, clearer
signal in fewer playtest cycles). User chose 14% on the reasoning that
exploratory tuning benefits from decisive jumps; if 14 overshoots,
back off to 12 or 13 in v1.2. Confirmed alignment in this session.

**One thing to watch on next playtest.** The v1.0 addendum noted that
neighbor-bias creates clustered refills, which raises the rate of
natural 5+/7+ matches in the refill (and thus natural special-tile
creation) independent of the queued big-turn drop. At 14% that
compounding gets stronger. The user explicitly named this as one of
the things they're tuning *for* ("increased specials on cluster refill
→ more fun"). If it tips into chaotic instead of fun, the bias rate is
the first lever to dial back, not the big-turn drop mechanism.
