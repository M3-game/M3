## Addendum — 2026-07-03 Session 3: tutorial panels 3–6 reviewed, refined & merged (tablet v11.21)

Reviewed the first-draft panels 3–6 (bomb, cross, supernova, hypernova) with the
user on the `tutorial-panels-3-6` branch, refined them, then merged to `main`.

### What shipped

- **`core/Tutorial.jsx` (edit-in-place):**
  - **Refill variety.** After any blast, the refill now starts each new cell's
    color search at a position-derived offset and cycles through all six tile
    types (still rejecting any that would complete a run). This fixes the
    red/blue wash the earlier greedy scan-from-red produced on the big-blast
    panels (3–6). Still deterministic — same board every replay.
  - **Panel 4 (cross) board.** Two tiles recolored. (3,2) green→red removes a
    4-match alternative to the taught 3-match trigger: the cross is green, so a
    green sliding into the trigger cell would line up a green 4 (a better-looking
    move we must not leave on screen). (2,1) orange→blue stops the trigger swap
    from leaving an uncleared incidental row-2 match — the tile the swap
    displaces upward no longer lands beside a same-color pair.
  - Panels 3, 5, 6 were sim-verified free of the same incidental-match issue:
    they make their special with a **vertical** drag, so the displaced tile
    lands with no matching neighbors. Panel 4 was the only one affected (its
    make-move is horizontal).
- **Tablet arcade v11.20 (draft) → v11.21:** finalized — draft markers removed
  from the header comment, in-game label, and `index.html`. `sections` unchanged
  (all six shared panels). No arcade gameplay/scoring/board-render change.

### Verification

- `npm run build` clean. Every panel's full make→use sequence was replayed in a
  node simulation: run-free at start and after each drop, the make produces
  exactly the intended special, and the trigger swap yields exactly one match
  (the intended one) fully inside the blast footprint — no leftovers.

### Not addressed / next session

- Panel 7 (multipliers — needs the `core/gameLogic.js` scoring extraction) and
  panel 8 (fusion finale).
- Real-device playtest of the tutorial → user.

## Addendum — 2026-07-03: scoring extraction (v11.22) + tutorial panel 7 (v11.24)

Later the same day, built the second half of the panel-7 plan.

**Scoring extraction (tablet v11.22, merged):** lifted the pure scoring math into
`core/gameLogic.js` — `getCascadeMultiplier` + seven point constants
(match/L-shape/line/bomb/cross/supernova/hypernova); `getMultiplier` was already
there but the tablet used a byte-identical local copy. Proof-by-construction
no-op (each literal → equal-valued constant; identical functions), verified by
build + 25/25 tests. Phone carries the same values and can adopt the module
later.

**Panel 7 — scoring multipliers (tablet v11.23 draft → v11.24 final, merged):**
a paced turn whose scores are the REAL in-game values. Swap makes 2 matches
(combo), the fall makes a 3rd (cascade), a bomb + line chain — 120 → 1,800 vs a
basic ~+60. Engine additions in `core/Tutorial.jsx`: a combo/multiplier readout
(decision C — honest `×N pts`, not the game's `x{count+1}` headline), match
highlight boxes, popup placement, `specials`/`reference` fields, and a blast
`except` (spare a chained special). Review round 1 (9 items) all addressed —
notably the HONEST cascade: the fall's 3rd match includes the bomb so it
genuinely fires, and its blast chains into the line. Verified: a special fires
when part of a color match, and blasts chain (both confirmed in game code);
turn sim-verified (start run-free, match includes the bomb, positions stable).

## Addendum — 2026-07-03: tutorial panel 8 (fusion) — all 8 shared panels done (v11.26)

Built the last shared panel. **Fusion** shows three fusions in ascending order,
each on a fresh board: line+line `⚡⚡ DOUBLE LINE! +700`, then bomb+bomb
`💣💣 MEGA BLAST! +1500`, then hypernova+supernova `🌠🌌 NOVA FUSION! +8000` —
real popups + points from the game's `activateSpecialCombination`. Because a
fusion's blast would wipe out the next demo's specials, a new `setup`
board-reset step gives each fusion a clean board; a climbing "fusion ladder"
tally keeps all three values in one view (the escalation is the lesson). Built
v11.25 (draft) → reviewed → v11.26 (final), merged. Engine additions in
`core/Tutorial.jsx`: the `setup` step + the `onLadder` tally. Filler board
sim-verified run-free.
