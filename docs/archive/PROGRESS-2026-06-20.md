## Addendum — 2026-06-20 bonus-move shared wallet (update-list item a)

### What shipped

Bonus moves became a **single persistent wallet shared between Verses
and Arcade**, per device family. 5 platform version bumps:
verses v1.14→v1.15 (tablet) / v1.9→v1.10 (phone) / v1.8→v1.9 (sandbox),
arcade v13.5→v13.6 (phone) / v11.16→v11.17 (tablet).

Behavior:
- Pool hydrates from the shared key at mount and persists on every
  change, in both Verses and Arcade — never lost across passage-switch,
  picker, "Play again", browser close, or the Verses→Arcade→Verses
  round trip.
- The 4 artificial Verses resets (handlePick, handleBackToPicker,
  restartGame VERSES_MODE block, wrapper onRestartGame) were removed —
  the pool now only changes on earn/spend.
- "Arcade mode" handoff simplified: under a shared pool there's nothing
  to transfer, so it just navigates. The old add-to-key + "+N carried"
  carry-receipt banner is retired.
- "Arcade mode" button added to single-level passages' end screen
  (Titus, Psalm 23, Psalm 46).
- Cap 99→999, near-cap warning 90→900, applied to **all 5 platforms**
  (verses + the two arcades that share the pool).

### Scoping evolution (decisions changed mid-discussion)

The ask started narrow ("bonus moves saved across games in Verses") and
grew through scoping:
1. Locked a single always-persistent pool (never auto-resets).
2. Initially chose Option A — a Verses-only pool, separate from Arcade.
3. User then asked for round-trip persistence Verses⇄Arcade, which
   flipped the decision to a **shared wallet (Option B)**. Turned out to
   be *less* code: both Verses platforms already used the Arcade storage
   key but artificially forced themselves to 0 on entry — removing that
   reset + persisting was the whole change. Accepted consequence: Arcade
   and Verses bonus moves now mix (one wallet).
4. Cap → 999 (user wants headroom, "don't want to be limited").
5. **Cross-platform consequence flagged + accepted:** because the wallet
   is shared, the 999 cap must also apply on the Arcade side, or the
   arcade earn-clamp (`Math.min(prev+earned, CAP)`) would slam a >99
   shared pool back to 99. User approved bumping the two Arcade caps too
   (scope grew from 3 → 5 platform files).
6. User asked to add the "Arcade mode" button to single-level passages.

### Sandbox note

Sandbox uses a sandbox-scoped key the real arcade doesn't read, so its
wallet is self-contained (persists within Sandbox Verses). Its "Arcade
mode" button navigates to the real phone arcade but carries nothing —
acceptable for a dev fork.

### Build + verification

Build clean (`npm run build`). Verified all 4 `setBonusMoves(0)` resets
removed from each Verses file (0 remaining) and all 5 caps read 999.
