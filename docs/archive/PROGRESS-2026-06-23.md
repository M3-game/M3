## Addendum — 2026-06-23 play-through options (item b)

### The note that prompted this (corrected, in full)

The June-20 update list recorded item (b) as a compressed phrase — "New
pre-game selection: replay a single level 2–4×; for multi-level games,
'one level at a time' vs. 'whole game.'" — that lost the original intent
(the user's English sentences were never written down in fuller form, so
they couldn't be recovered from git). Reconstructed with the user
2026-06-23, **(b) is two related features**:

1. **"Play N times" drill.** Before a level starts, choose to play it
   **2–4× continuously** — a short passage (a 10-move level is too short
   to be satisfying *as a game*) becomes a longer run that's both more
   fun and better for memorization. One unbroken session: the passage
   loops, one running score, total moves = N × chunks − 1 (chunk 0 free
   only on the first pass; repeats swap through everything). Applies to
   single-level passages and to each level of a multi-level game.
2. **"Repeat level" button.** A quick post-win replay on the one
   end-screen that lacked it (multi-level, middle level, first-pass win).

### What shipped (tablet-verses v1.16 → v1.17)

- **Rep selector** (1×/2×/3×/4×) on the start-of-round modal
  (`showStartModal`). Offers only counts whose drill total stays ≤ **60
  moves** (the ceiling); unchoosable counts are omitted; if only 1× fits,
  no selector shows. "Begin" seeds the round from the chosen rep count.
- **Continuous drill:** `selectedPlays` threads into
  `versesFlattenLevel(game, levelIndex, plays)`; `revealedChunkIndex`
  wraps mod `totalChunks` when reps > 1; move budget = N × chunks − 1.
  Resets to 1× per level (wrapper remounts on `slug:levelIndex`).
- **"Pass X of N"** header indicator during a drill.
- **"Repeat level"** button on the middle-level first-pass win screen
  (replays at the rep count just played via `restartGame`;
  completion/stars/best never regress; "Next level" stays).
- **Tiered target multiplier** (`versesTargetForMoves`), Option A —
  applies to ALL play, replacing the uniform × 300:
  `<17 →×300, 17–24 →×500, 25–29 →×600, +×100 per +5 moves`. No ceiling
  on the multiplier yet — deferred to the verses simulation work
  (TODO #9) rather than guessed. A single play still honors an explicit
  per-level `targetScore` (only Titus has one, = the formula anyway).

### Key decisions (scoping, 2026-06-22 → 06-23)

- **Continuous drill** chosen over discrete reps (matches the user's
  21/43-move math: repeats don't re-grant the free first chunk).
- **Scaled target counts normally** (Option A): drilling unlocks levels
  / records stars like a normal play, just on the longer length.
- **4× cap** with a **60-move ceiling** limiting offered rep counts.
  Distribution check (35 levels): median 12 moves, max 28; uncapped 4×
  ran 31→115 moves, 11 of 35 over 55 — confirming a ceiling was needed.
- **Tier multiplier guessed-and-adjust** per user call; the verses sims
  (TODO #9) will tune it later. Long-run super-linear scoring (deep
  combos compound) is the rationale for steeper tiers.

### Length-distribution snapshot (informed the ceiling)

35 levels across 15 games: min 7 / median 12 / p90 23 / max 28 moves.
Bands: ≤10 → 4 levels, 11–16 → 23, 17–24 → 7, 25+ → 1 (Matthew 5 L7).

## Addendum — 2026-06-23 Session 1: drawing code → `core/` (tablet v11.18)

First coding step of the tutorial plan (verses TODO #4) and the first
increment of the "move shared code into `core/`" architecture item
(DEFERRED.md). Scoped earlier the same day.

### What shipped

- **New `core/tileDrawing.js`** — the canvas tile-drawing cluster
  (`TILE_COLORS` palette + `drawTile` + the six shape helpers
  `drawHypocycloid`…`drawSun` + `drawSpecialIcon`), extracted **verbatim**
  from tablet v11.17 (lines 364–902). Pure drawing: depends only on the
  canvas context + arguments, no game state or other constants — which is
  why it was the lowest-risk possible first extraction. Exports
  `TILE_COLORS`, `drawTile`, `drawSpecialIcon`; the six shape helpers stay
  internal (only `drawTile` calls them).
- **Tablet arcade v11.17 → v11.18** — the ~540-line drawing block removed
  and replaced with `import { TILE_COLORS, drawTile, drawSpecialIcon } from
  '../../core/tileDrawing.js'`. No gameplay/scoring/visual change. (Note:
  `TILE_COLORS` is used outside the drawing code too — a tile-type name
  lookup — so it's imported alongside the two draw functions.)

### Verification

- **Byte-identical:** `diff` of original tablet lines 364–902 vs. the new
  core module (accounting only for the added header + three `export`
  keywords) → **IDENTICAL**. The tiles cannot render differently.
- `npm run build` clean. v11.18 defines none of the drawing functions and
  imports all three. Lint hints in the moved code are pre-existing
  (`isMatched`/`color` were already unused params upstream) — left as-is to
  keep the extraction verbatim.

### Why this matters beyond the tiles

This was the first live test of the "incremental extraction works in
practice" thesis (DEFERRED.md). It worked cleanly on a real, most-played
platform with zero behavior change — encouraging signal for migrating the
other platforms later and for building the tutorial on shared drawing code.
